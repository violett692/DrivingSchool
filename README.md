# Автошкола: система формування та управління розкладом занять

Спільний курсовий проєкт двох студенток з дисципліни «Об'єктно-орієнтоване програмування».
Мова C# 12, платформа .NET 8, інтерфейс WPF (шаблон MVVM), база даних SQLite через Entity Framework Core 8, модульні тести xUnit.

## 1. Що потрібно встановити

| Програма | Навіщо | Де взяти |
|---|---|---|
| Windows 10 (64-біт) або Windows 11 | WPF працює лише у Windows | — |
| **Visual Studio 2022 Community** (версія 17.8 або новіша), робоче навантаження **«.NET desktop development»** (Розробка класичних застосунків .NET) | відкриття, збірка і запуск рішення | https://visualstudio.microsoft.com/vs/community/ |
| *або* **.NET 8 SDK** (x64), якщо Visual Studio не потрібна | збірка і запуск з командного рядка | https://dotnet.microsoft.com/download/dotnet/8.0 |
| Інтернет під час першої збірки | автоматичне завантаження пакетів NuGet | — |

Пакети NuGet окремо встановлювати не потрібно, вони завантажуються автоматично під час першої збірки:

| Проєкт | Пакет | Версія |
|---|---|---|
| DrivingSchool.Core | Microsoft.EntityFrameworkCore.Sqlite | 8.0.11 |
| DrivingSchool.Tests | Microsoft.NET.Test.Sdk / xunit / xunit.runner.visualstudio | 17.11.1 / 2.9.2 / 2.8.2 |

Базу даних встановлювати не потрібно: SQLite вбудована в програму.

## 2. Запуск у Visual Studio (рекомендовано)

1. Розпакуйте архів, наприклад у `Документи\DrivingSchool`.
2. Двічі клацніть файл **`DrivingSchool.sln`** (відкриється Visual Studio).
3. Дочекайтеся, поки в нижньому рядку зникне напис про відновлення пакетів (Restoring packages), це 1–2 хвилини.
4. У «Обозревателе решений» (Solution Explorer) клацніть правою кнопкою на **DrivingSchool.App** → **Назначить автозагружаемым проектом** (Set as Startup Project).
5. Натисніть **F5** (або зелену кнопку ▶ DrivingSchool.App).
6. Відкриється вікно «Автошкола: розклад і навчальний процес» з вісьмома вкладками.

## 3. Запуск без Visual Studio (лише .NET 8 SDK)

У папці проєкту двічі клацніть:
- **`1_ЗБІРКА_І_ТЕСТИ.cmd`** – збирає рішення, запускає всі тести, зберігає журнал у `test-log.txt` і відкриває програму;
- **`2_ЗАПУСК_ПРОГРАМИ.cmd`** – збирає і запускає лише програму.

Або вручну в командному рядку з папки проєкту:

```
dotnet restore DrivingSchool.sln
dotnet build DrivingSchool.sln -c Release
dotnet run --project src\DrivingSchool.App -c Release
```

## 4. База даних

Під час першого запуску поруч із програмою (`...\bin\...\drivingschool.db`) автоматично створюється файл бази SQLite
і наповнюється демонстраційними даними: 4 автомобілі, 4 викладачі, 2 групи, 10 учнів, розклад за 3 минулі, поточний
і наступний тижні, записи на водіння, відвідування, оцінки. Схему створює Entity Framework Core (`EnsureCreated`),
дані додає клас `DbInitializer`.

Щоб почати з чистої бази, закрийте програму і видаліть файл `drivingschool.db` – він створиться знову.

## 5. Тестування

- У Visual Studio: меню **Тест → Запустить все тесты** (Test → Run All Tests), результат у вікні «Обозреватель тестов».
- З командного рядка: `dotnet test DrivingSchool.sln`

У проєкті 30 тестових методів (33 тестові випадки): `SchedulingTests` (модуль 1) і `LearningTests` (модуль 2).
Результат на Windows 11, .NET SDK 8.0.428: **Всього тестів: 33, пройдено: 33, не пройдено: 0**.
Ті самі збірка і тести автоматично виконуються на GitHub (вкладка **Actions**, файл `.github/workflows/build-and-test.yml`).

## 6. Можливі проблеми

| Симптом | Причина і рішення |
|---|---|
| «Не вдалося відкрити базу даних … Політика управління програмами заблокувала цей файл (0x800711C7)» | Увімкнено Smart App Control у Windows 11, він блокує щойно зібрані DLL. Запускайте через **`2_ЗАПУСК_ПРОГРАМИ.cmd`**: він збирає програму з вбудованою бібліотекою (`-p:EmbedCore=true`). |
| Visual Studio пише, що не знайдено .NET 8 / net8.0-windows | Встановіть у Visual Studio Installer навантаження «.NET desktop development» або .NET 8 SDK. |
| Помилка NU1101 / не вдалося завантажити пакети | Немає інтернету під час першої збірки; підключіться і повторіть збірку. |
| Скрипт `.cmd` не запускається («Windows захистив ваш ПК») | Натисніть «Докладніше» → «Однаково запустити». |
| Пункт «Назначить автозагружаемым» відсутній | Клацніть правою кнопкою саме на проєкті DrivingSchool.App, а не на рішенні. |

## 7. Структура рішення

```
DrivingSchool.sln
├── src/DrivingSchool.Core          бібліотека бізнес-логіки
│   ├── Models/                     класи предметної області (спільні)
│   ├── Data/                       AppDbContext, DbInitializer (спільні)
│   ├── Common/                     IEntity, Repository<T>, IClock, DrivingHoursCalculator (спільні)
│   ├── Scheduling/                 МОДУЛЬ 1: облік ресурсів і формування розкладу
│   └── Learning/                   МОДУЛЬ 2: запис, відвідування, успішність
├── src/DrivingSchool.App           WPF-застосунок (MVVM): Views, ViewModels, Infrastructure
└── tests/DrivingSchool.Tests       модульні тести xUnit
```

## 8. Розподіл функціоналу між студентками

| Студентка 1: облік ресурсів і розклад (гілка `feature/scheduling`) | Студентка 2: запис, відвідування, прогрес (гілка `feature/learning`) |
|---|---|
| `Scheduling/ResourceService` – облік учнів, інструкторів, автомобілів, груп | `Learning/BookingService` – запис на слоти водіння, ліміти, залишок годин |
| `Scheduling/ScheduleRules`, `ScheduleConflictChecker` – 7 правил розкладу | `Learning/AttendanceService` – журнал відвідувань після завершення заняття, оцінки |
| `Scheduling/ScheduleService`, `ScheduleGenerator` – ручне і автоматичне формування розкладу | `Learning/ProgressService`, `ReportService` – прогрес, допуск до іспитів, звіт CSV |
| Вкладки «Учні», «Інструктори», «Автомобілі», «Групи», «Розклад» | Вкладки «Запис на водіння», «Журнал відвідувань», «Успішність і прогрес» |
| `SchedulingTests` | `LearningTests` |

Спільна частина (моделі, база даних, правило обліку годин, головне вікно) створена разом.
